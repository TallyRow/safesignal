# Contract: on-disk surface + allow-file schema

Both files live under `api/` (which is **not** in `package.json` `files`, so neither ships to
consumers). Both MUST be deterministic and contain only public-type information (FR-013).

## `api/surface.json` — the frozen baseline (a `PublicSurface`)

```jsonc
{
  "version": "1.3.0",            // package.json version at extraction time
  "symbols": [                    // sorted by (entry, name) for stable diffs
    {
      "entry": ".",
      "name": "createLogger",
      "kind": "function",         // function | class | interface | type | const | enum
      "signature": "(options?: CreateLoggerOptions) => Logger",
      "deprecated": false
    },
    {
      "entry": "./transport-beacon",
      "name": "createBeaconTransport",
      "kind": "function",
      "signature": "(options?: BeaconTransportOptions) => Transport",
      "deprecated": false
    }
    // ...one entry per exported symbol across all four entry points
  ]
}
```

**Rules**
- `symbols` sorted ascending by `entry` then `name`.
- `signature` is the normalized shape for the `kind` (see data-model.md). Import-path and
  whitespace noise is normalized out so only meaningful changes register.
- Serialization is byte-stable (fixed indentation, stable key order, trailing newline) so an
  unchanged surface re-extracts identically (Principle IX).
- Regenerated by `npm run api:extract` **only at release time**; frozen between releases.

## `api/surface-allow.json` — reviewed compatible-change overrides (`AllowEntry[]`)

```jsonc
[
  {
    "entry": ".",
    "name": "createLogger",
    "from": "(options?: CreateLoggerOptions) => Logger",
    "to":   "(options?: CreateLoggerOptions, signal?: AbortSignal) => Logger",
    "reason": "Added trailing optional parameter; existing call sites unaffected.",
    "reviewedBy": "maintainer-handle"
  }
]
```

**Rules**
- Default content is the empty array `[]`.
- An entry suppresses a CHANGED finding **only** when `(entry, name, from, to)` matches the exact
  observed transition; a stale/imprecise entry does not excuse an unrelated change.
- Entries are remediation debt for the current cycle; they are removed when the baseline is
  refreshed at release (the change is folded into `surface.json`).
- Adding an entry is visible in PR review — a human acknowledges the change is backward-compatible
  (keeps the override auditable, not a silent skip — Principle X).

## Release freshness assertion

At release (`release.yml`, alongside `changelog-validate`), CI MUST assert that
`api/surface.json` equals the surface extracted from the tagged commit's build. A mismatch fails
the release, forcing the maintainer to run `npm run api:extract` (and clear the allow-list) before
tagging — so every published version becomes the next baseline (FR-007), mirroring the
CHANGELOG-first discipline.
